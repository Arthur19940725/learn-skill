## Learning Ladder

Use exactly five levels:

1. Level 1: Complete Beginner
2. Level 2: Basic Understanding
3. Level 3: Practical User
4. Level 4: Problem Solver
5. Level 5: Confident Practitioner

For every level, include:

1. **本级应该理解什么**
2. **最高杠杆的概念或技能**
3. **可观察的 mastery 表现**
4. **动手练习或 mini-project**
5. **可测量的晋级里程碑**
6. **常见错误及纠正方法**
7. **晋级前自检问题**

Increase difficulty from vocabulary and intuition, through common tasks, to diagnosis, independent delivery, trade-offs, and edge cases. End with missing prerequisites, evidence-based starting level, and one action possible today. Define milestones through behavior or artifacts.

## 20-Hour Plan

Frame 20 hours as a usable-foundations target, not expert mastery. Start with scope, assumptions, exclusions, high-leverage content, concept connections, and prerequisites.

Create exactly 10 sessions of 120 minutes around one cumulative project. Keep delivery bounded:

- First execution turn: provide the scope sections, a 10-row session map, then full details for Sessions 1–2.
- Each later `continue` turn: provide the next two full sessions.
- Final turn: provide Sessions 9–10, final project, rubric, failure recovery, one shallow-understanding edge case, and post-plan direction.
- End every batch with `Covered: Sessions X–Y` and `Remaining: Sessions ...`.
- If the user explicitly requires one complete file and output capacity is sufficient, combine the same batches into that file without dropping fields.

Every detailed session includes:

- **Main learning goal**
- **Time allocation** whose blocks total exactly 120 minutes
- **Key concepts or skills**
- **Practical exercise / mini-project**
- **One resource with verification status**, exact part to use, and task binding
- **Concrete deliverable**
- **Measurable completion criterion**
- **Exactly 5 active-recall questions**
- **Compact answer key**, clearly separated after the questions

The 10-row map contains stable session ID, goal, cumulative-project increment, and completion evidence. Do not duplicate the full detailed fields in the map.

Resource branch:

- With live verification: use direct primary sources and state `Verified: YYYY-MM-DD`.
- Without live verification: state `Unverified candidate`; never claim current availability, price, version, or a checked date.

Recalculate `10 × 120 minutes = 1,200 minutes = 20 hours` before the final batch.

## Edge Quiz

Run 10 main questions across turns. Ask only one unanswered question per response.

Difficulty bands:

- Questions 1–3: foundational
- Questions 4–6: intermediate application
- Questions 7–8: advanced reasoning
- Questions 9–10: expert synthesis or edge cases

Each main question has one primary gradable action. State required assumptions. Before the learner answers, reveal no answer, hint, later question, score, or revision plan.

After answers to Questions 1–9, output in order:

1. **Score: X/10**
2. **答对的部分**
3. **精确缺口、错误或薄弱假设**
4. **只重讲缺失部分** with one example
5. One next question determined by the routing below

Use rubric: accuracy 4, completeness 2, reasoning/application 2, clarity 2. Name deducted dimensions.

Apply this routing only after Questions 1–9:

- `< 7/10`: ask one targeted follow-up; score it once, keep the original main score, then move to the next main question. A follow-up never creates another follow-up.
- `7–8/10`: ask the next main question at planned difficulty.
- `9–10/10`: ask the next main question with slightly stronger application or boundary demands.

After a follow-up answer, briefly score and repair it, then ask the next main question. Do not apply the main-question routing to follow-up scores.

After Question 10, never create Question 11:

- `7–10/10`: close immediately with the final report.
- `< 7/10`: ask one final targeted follow-up, grade it once, then close with the final report regardless of that follow-up score.

Track main-question number, 10 original main scores, follow-up scores, strengths, weaknesses, and misconceptions. The final report averages only original main scores and contains strongest and weakest areas from answer evidence, misconceptions, a prioritized revision plan, then five non-interactive final challenge questions without answers. Those five form the sole exception to one-question output.

## Cheat Sheet

Produce compact Markdown for about five minutes of review: roughly 600–900 English words or 1,000–1,600 Chinese characters. Treat “one page” as an information budget, not a print guarantee.

Include in order:

1. **一句话定义**
2. **核心 mental model**
3. **重要概念、规则、公式、命令或步骤**
4. **最小有用视觉**, only when it improves understanding
5. **3–5 个具体例子**
6. **常见错误、易混点和重要例外**
7. **Before You Use This checklist**
8. **Exactly 5 rapid-recall questions**

State scope, purpose, prerequisites, assumptions, units, variables, version, jurisdiction, or date boundary where relevant. Preserve safety limits. Omit history and low-value repetition before dropping critical caveats. Do not include answers by default. End with one sentence naming intentional omissions.

## Resource Path

Requires live verification or user-supplied sources. Without either, stop at one question asking for browsing/source access or explicit acceptance of `unverified candidates`; do not fabricate a “best/current” list.

Once five records are available—live-verified, user-supplied, or explicitly accepted as unverified—choose exactly five complementary resources. For each, include exactly:

1. **Name, creator, direct link**
2. **Type**
3. **Why it earns one of five slots**
4. **Specific subtopic covered best**
5. **Best learner profile**
6. **Difficulty**: beginner / intermediate / advanced
7. **How to use it**: sections to use and skip
8. **Estimated time and cost**
9. **Limitation or warning**

Also state language, prerequisites, verification status, and any individually `unverified` fields. Only verified records receive a verification date; never attach a date to accepted unverified candidates. Reject highly redundant choices. Bind every resource to a learner task and output.

Then provide ranked order with dependency reasons, a seven-day path using only those five resources, and a coverage gap. Every day needs realistic time, task, hands-on deliverable, and pass/fail completion criterion.

## Feynman Loop

Run at most three teach-back rounds. Narrow overbroad topics to the confirmed coherent scope.

First round:

1. Explain briefly in plain language appropriate for a smart 12-year-old.
2. Explain causality and connections, not only facts.
3. Use one concrete example and one analogy.
4. Define unavoidable jargon and state where the analogy fails.
5. Ask only for a teach-back, then wait.

After each teach-back:

1. Identify correct parts.
2. Find important gaps, errors, hidden assumptions, and vague phrases.
3. Label each as factual error, missing depth, or unclear wording.
4. Re-teach only the highest-value gap with one concrete example.
5. Ask for another teach-back only when completion criteria are unmet and fewer than three rounds have occurred.

Complete early when the learner accurately explains the mechanism and relationships, gives a correct example or prediction, covers agreed scope, and has no misuse-causing misconception. After round three, stop even if gaps remain; list targeted practice rather than repeating the same explanation.

Close with final clean explanation, one-sentence mental model, remaining weak points, and a three-question non-interactive practice bank. Make at least one question test transfer to a changed scenario. The practice bank is not a request to answer all three in the current turn; the learner can choose one or ask to continue one question at a time.

### Feynman worksheet

```markdown
# Concept and scope
## My plain-language explanation
## Concrete example or prediction
## Where my explanation becomes vague
## Gap to repair
## Cleaner next explanation
## Transfer question
```

## First-Principles Decomposition

1. List irreducible axioms, primitives, constraints, or conservation relationships.
2. Build higher-level concepts step by step without skipping dependencies.
3. Include at least two explicit counterfactual checks: “If this were false, what would break?”
4. Separate derived conclusions from definitions, conventions, and empirical rules.
5. Reconstruct the complete topic from primitives in one compact paragraph.
6. End with exactly one unanswered, gradable derivation challenge whose result was not directly taught.

Wait for the learner after the challenge. Complete when the learner independently derives a non-obvious consequence.

## Simon-Style Mastery Sprint

Use for a broad field, multi-week plan, or real project. Treat duration as a planning assumption.

1. Define an observable performance target.
2. Build a prerequisite-ordered chunk map.
3. Mark each chunk `unknown / recognized / explainable / applicable / fluent`.
4. Select only the current highest-value chunk for the active sprint.
5. Combine worked examples, retrieval, deliberate practice, and a real output.
6. Name a fast feedback source: tests, answer key, learner, peer, or expert.
7. Advance only after a no-notes checkpoint passes.
8. Give calendar-time estimate, three actions possible today, and overall exit criteria.

## SQ3R Reading

Use for a supplied textbook, paper, chapter, or report.

1. **Survey**: scan abstract, headings, figures, conclusion, and structure.
2. **Question**: turn learning goal and headings into answerable questions.
3. **Read**: read to answer those questions, not to highlight indiscriminately.
4. **Recite**: close the source and answer from memory.
5. **Review**: compare, repair exact gaps, summarize argument, and schedule retrieval.

Classify the source, then select six cue categories:

- **Empirical research paper**: research question, method, evidence/data, result, limitations/alternatives, implications.
- **Conceptual chapter or technical standard**: purpose or central claim, key concepts or requirements, mechanism or structure, examples or rationale, exceptions or limits, applications.
- **Report or case study**: scope, system or context, timeline/evidence, causal analysis, uncertainties/limitations, decisions or actions.

Distinguish source statements, deductions, and supplemental background. When producing a worksheet before the learner performs retrieval, fill source-grounded Survey, Questions, and Read scaffolding only; leave Recite and learner-owned Review fields blank. Record the main argument, strongest evidence, remaining gap, and next recall date only after the learner supplies an actual closed-source attempt.

## Pomodoro Focus Session

1. Define one visible deliverable for the current block.
2. Remove likely distractions and capture intrusive ideas in a parking list.
3. Default to `25 minutes focus + 5 minutes genuine rest`.
4. After four blocks, use a 15–30 minute long rest.
5. After every completed block, record output, blocker, and next step. When generating a future session, leave completion, blocker, output-produced, recall-result, and next-step evidence fields blank until the learner reports actual execution.

Adapt intervals for task and accessibility while preserving bounded focus, real rest, and concrete output. Do not fill breaks with another high-cognitive-load task.

## Cornell Notes

Create four explicit areas:

- **Header**: topic, source, date, learning goal.
- **Main notes**: ideas, evidence, examples, formulas, uncertainties, and source locations.
- **Cues**: questions, keywords, retrieval prompts, and likely assessment points added after learning.
- **Summary**: learner-owned short synthesis written from memory with the source closed.

Use cue questions as a self-test by hiding main notes. When generating notes before the learner attempts retrieval, leave Summary and Self-test fields blank and instruct the learner to close the source before filling them. Record results only after the learner supplies actual recall evidence.

```markdown
# Topic / Source / Date
Learning goal:
| Cues and questions | Main notes and evidence |
| --- | --- |
| Add after learning | Capture ideas, locations, examples, and uncertainties |
## Summary from memory
## Self-test
- Correct:
- Missing:
- Review date:
```

## Quick Active Recall

1. Plan 3–7 increasingly difficult questions mixing definition, mechanism, comparison, application, error diagnosis, and transfer.
2. Ask one question at a time; reveal no answer before an attempt.
3. Correct: deepen one level. Partial: separate correct and missing parts. Incorrect: give correct answer and retrieval cue.
4. Finish only after at least 80% correct on a fresh question set.

Switch to Edge Quiz when the user requires exactly 10 questions, graded difficulty bands, or finding their limit.

## Spaced Review

1. Create about 10–20 atomic recall units with stable IDs; each tests one fact, distinction, command behavior, or skill.
2. Default cadence: Day 0, 1, 3, 7, 14, 30, 60, 120. Respect a user-specified cadence when different.
3. For every review, name unit IDs, retrieval format, time budget, and measurable success criterion.
4. Use comparison, diagnosis, application, and transfer in later reviews instead of identical cards.
5. After failed recall, shorten the next interval and repair the exact failed unit.
6. Output executable Anki tags, Markdown checklist, or calendar-ready entries for the confirmed tool.

## Smart Summary

1. Identify 3–5 named load-bearing ideas; removing one must materially damage the model.
2. Wrap each in a mental model or framework; use metaphor only when useful.
3. Produce exactly three artifacts: one single-sentence summary, one labeled boxes-and-arrows diagram, and a cheat sheet with fewer than 20 substantive bullets grouped by framework.
4. For every framework, state `when to use` and `when not to use`.

Remove redundant bullets until every remaining bullet preserves real information. Switch to Cheat Sheet when the user explicitly wants a one-page or five-minute reference.

## Weakness Diagnosis

Initial diagnosis:

1. Plan 8–12 questions spanning sub-areas and mixing recall, application, edge cases, and why questions.
2. Unless the user requests a batch exam, ask only Question 1 and wait; continue one at a time until evidence is sufficient.
3. Do not classify untouched sub-areas from guesswork.

After enough evidence, classify each sub-area:

- `Solid`: evidence supports moving on.
- `Shaky`: needs reinforcement.
- `Misconception`: wrong model must be unlearned before relearning.
- `Blind spot`: learner did not recognize the sub-area.

For every non-Solid item, cite answer evidence, prescribe one targeted exercise, and name the next learning method. Prioritize by conceptual dependency or practical risk. Re-test only weak sub-areas after seven days, with observable pass criteria. Stop when every area is Solid or has an exercise and scheduled re-test.

## Integrated 90-Minute Session

Use only when SQ3R, Pomodoro, and Cornell are jointly confirmed for one source. This template is self-contained.

Classify the source before scheduling. Choose six cue categories for the source type:

- **Empirical research paper**: research question, method, evidence/data, result, limitations/alternatives, implications.
- **Conceptual chapter or technical standard**: purpose or central claim, key concepts or requirements, mechanism or structure, examples or rationale, exceptions or limits, applications.
- **Report or case study**: scope, system or context, timeline/evidence, causal analysis, uncertainties/limitations, decisions or actions.

Preserve the six-slot structure while replacing labels with the selected source-type categories. When generating the session before it is performed, fill only source-grounded schedule, cues, and main-note scaffolding; leave learner-owned retrieval fields blank. Never predict the memory summary, remaining gap, retrieval result, next target/date, or updated chunk status. Fill those only after the learner supplies actual closed-source evidence.

```markdown
# Topic / Source / Date
Source type:
Learning goal:
Current chunk:
Chunk status: unknown / recognized / explainable / applicable / fluent

## 0–5 minutes: Survey and questions
- Survey structure, figures, abstract or introduction, and conclusion.
- Choose six cue categories for the source type and turn them into answerable questions.

## 5–30 minutes: Focus block 1
- Read to answer those questions.
- Capture evidence and source locations in Cornell main notes.

## 30–35 minutes: Genuine break
- Leave the source and do no other cognitive task.

## 35–60 minutes: Focus block 2
- Apply, compare, solve, or build one artifact.
- Add evidence and uncertainties to main notes.

## 60–65 minutes: Genuine break
- Leave the source and do no other cognitive task.

## 65–80 minutes: Closed-source SQ3R Recite / teach-back
- Close all sources.
- Explain the source's purpose or claim, mechanism or structure, support, boundaries, and implications using the selected cue categories.
- Mark exact gaps before checking.

## 80–90 minutes: Cornell close and retrieval setup
- Put six questions and weak-point prompts in cue column.
- Close the source, then have the learner write the summary from memory.
- After the learner attempts retrieval, record the evidenced gap, next target, next recall date, and updated chunk status.
```
